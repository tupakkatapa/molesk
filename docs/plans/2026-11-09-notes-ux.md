# Plan: notes UX — configurable surface, index pages, finished editor

> Superseded by [2026-11-09-hardening-and-polish.md](2026-11-09-hardening-and-polish.md).

## Goal

molesk should feel like a finished product in both of its roles:

- a published docs/blog site (read-only);
- a private notes app (read-write).

Every surface element should be a switch with a sensible default for that role.

## Success criteria

- One option table (CLI flag ⇄ module option ⇄ default per mode) covers: edit, home, index, download, rss, source link, links, title, image, theme. The README documents it as a single table.
- Read-only defaults reproduce today's site exactly. The one exception is `/` with no home file; see Risks.
- Notes instance with defaults:
  - no RSS, no source link, no download, no footer;
  - an empty data dir shows an empty-state index with "New note", never an error.
- Sidebar:
  - every expanded folder, and the root, ends with a "+ New" row;
  - typing a name and pressing Enter creates the note and opens it; `name/` creates a folder;
  - empty folders are visible in edit mode.
- Editor:
  - same card and typography as the rendered note;
  - title field (rename/move);
  - autosave with visible status;
  - Markdown helpers (list continuation, indent, formatting shortcuts and a toolbar);
  - Write/Preview (side by side on wide screens);
  - delete goes to `.trash/`;
  - no system-font buttons; works one-handed on a phone.
- Folder index pages list children (newest first, with date and first-line excerpt). In edit mode they also hold folder actions (rename, delete when empty).
- Visual QA: screenshots of every screen, light and dark, at 390px and 1400px, attached to the PR. No element looks unstyled.
- Existing suite green. Every new behaviour has a spec that failed first.

## Non-goals

- WYSIWYG or contenteditable editing, a syntax-highlighting editor library (CodeMirror etc.).
- Full-text search: the sidebar gets a title filter only. Image upload. Multiple users. Version history (`.trash/` plus git/Syncthing cover recovery).
- Changing the read-only visual design beyond removing the Home special case.

## Approach

### Config model (single source)

| Concern         | Flag(s)                        | Module                        | Default read-only | Default `--edit` |
| --------------- | ------------------------------ | ----------------------------- | ----------------- | ---------------- |
| Write access    | `--edit`                       | `edit.enable`                 | off               | —                |
| Home page       | `--home <file>` / `--no-home`  | `settings.home` (str or null) | auto              | auto             |
| Index pages     | `--index` / `--no-index`       | `settings.index.enable`       | on                | on               |
| Download button | `--download` / `--no-download` | `settings.download.enable`    | on                | **off**          |
| RSS             | `--rss` / `--no-rss`           | `settings.rss.enable`         | on                | **off**          |
| Source link     | `--source` / `--no-source`     | `settings.source.enable`      | on                | **off**          |
| Links           | `--link icon:url`              | `settings.links`              | none              | none             |
| Theme           | `--theme dark\|light\|auto`    | `settings.theme`              | dark              | dark             |

- Every boolean gets both `--x` and `--no-x`. Defaults are resolved after parsing from one rule: _edit mode is a private notes app, so publishing features default off._ The `--no-*` flags behave exactly as before; nothing is removed.
- Module boolean options become `nullOr bool`, default `null` = "mode default", so the module never hard-codes a default the binary also decides. Same eval check as before: the read-only script must be byte-identical to `main`.
- **Home `auto`:** the first of `index.md`, `README.md`, `Home.md` at the root (case-insensitive). The home note opens at `/` and is hidden from the tree; the sidebar title links to `/`. The house icon and its `li.folder` special case go away.
- **`/` resolution:** home, else root index, else (index off) the first note. That last case is the legacy behaviour.
- **Folder URLs** `/content/<dir>/`: the folder's own `index.md`/`README.md` if present, else the generated index. Folder index is off → 404.

### Routing and server

- `lib/content.js` exposes one tree walk (`listFolder(dir)` → children with name, date, excerpt, isDir). The sidebar and index pages both render from it. In edit mode it includes empty folders.
- Index pages render through the existing `index.ejs` with an `index` local: one partial `views/folder.ejs`.
- Write API additions, each reusing `resolveWritable` + ETag preconditions + the per-path lock:
  - `POST /api/move` `{from, to}`: rename/move a note or folder. Fails with 412 on ETag mismatch, 409 if the target exists.
  - `PUT /api/dirs/<path>`: mkdir. 409 if the path exists as a file.
  - `DELETE /api/dirs/<path>`: removes an empty folder only, otherwise 409.
  - `DELETE /api/files/<path>`: moves the note to `.trash/<path>~<ISO-time>` instead of unlinking. `.trash` is a dot-dir, so it's hidden from the tree and from the write API.
  - `POST /api/preview` (text/markdown → HTML): the same markdown-it instance as the page renderer, so preview fidelity is exact.
- Empty data dir: `findIndexFile` no longer throws. `/` falls back to the empty index.
- Task lists: `- [ ]` / `- [x]` render as checkboxes (small markdown-it rule, or `markdown-it-task-lists` if it adds no build friction). In edit mode, clicking a checkbox in view mode toggles that exact source line through the ETag'd PUT.

### Sidebar

- **"+ New" row** as the last child of the root list and of every expanded folder (edit mode only). It is a full-width row (44px on touch), styled like the other tree rows with a muted `+`.
  - Activating it turns the row into an inline input with the placeholder "Note name — end with / for a folder".
  - Enter creates the note (PUT with `If-None-Match: *` and body `# <Name>\n\n`) and navigates to its editor with the caret on the body line. A name ending in `/` creates a folder and expands it.
  - Esc or blur on an empty input cancels. Inline errors are shown under the input (exists, invalid name).
- **Title filter** at the top of the tree (shown when there are more than 15 notes): client-side, matches on name, auto-expands matching folders.
- **Remove:** the floating new-note icon, the `<dialog>`, the Home row.

### Editor (`/edit/<path>`, rebuilt)

- **Layout.** The same card as the rendered note.
  - Header row: folder breadcrumb (small, muted) and the title input (content serif, h1 size). Editing the title renames the file on blur or Enter via `/api/move`.
  - Right side of the header: save status text ("Saved", "Saving…", "Offline — not saved"), a Preview toggle and a `⋯` menu (Download if enabled, Delete).
  - Body: an auto-growing textarea with no inner scrollbar. The page scrolls; 16px+ text so iOS doesn't zoom on focus. Monospace off by default, matching the note font size. Frontmatter stays in the text, untouched.
- **Autosave.**
  - Debounced 800ms after the last keystroke, plus an immediate flush on Ctrl/Cmd+S, blur, `visibilitychange`→hidden and `pagehide` (`fetch(..., {keepalive: true})`).
  - One request in flight at a time; the latest text is coalesced. Each response's ETag chains into the next request.
  - Dirty state means the text differs from the last acknowledged body. `beforeunload` warns only while dirty.
- **Conflict.** An inline banner, not a modal: "Changed elsewhere" with _Keep mine_ (overwrite) and _Load theirs_ (the current text is copied to the clipboard first).
- **Markdown helpers.**
  - Enter continues `- `, `* `, `1. `, `- [ ] ` and `> `; Enter on an empty item ends the list.
  - Tab / Shift+Tab indent and outdent list lines.
  - Ctrl/Cmd+B/I/K wrap bold, italic and link.
  - Formatting bar (bold, italic, heading, list, checklist, link, code): it sits in the header on desktop. On mobile it's pinned above the on-screen keyboard via `visualViewport`.
- **Preview.** Rendered via `/api/preview`, debounced. ≥1100px: side by side, toggle state persisted. Narrower: Write/Preview segmented control.
- **Done** (Esc or button) goes back to `/content/<path>`. `e` on a note page opens the editor.
- **Delete.** Opens an app-styled `<dialog>` that says "Moved to .trash", then navigates to the parent folder's index.
- **Mobile.** A slim sticky top bar on every page: menu, current title, and the primary action (Edit/Done). It replaces the floating hamburger. The content card goes edge to edge.

### Visual system

- One button style (icon, or icon plus label) in the content font and the existing palette. No browser-default buttons or inputs anywhere. Shared tokens (colours, radius, spacing) move to CSS custom properties in `base.css`; the dark theme overrides the tokens, not each rule.
- Focus rings are visible and on-palette. Hover styles only apply on `hover: hover`.

### Security and reliability (unchanged commitments, new surfaces)

- Every new path parameter (move `from`/`to`, dirs) goes through `resolveWritable`. Move takes the lock on both paths in sorted order.
- Move is a same-filesystem `rename`. The target is checked under the lock; the source ETag is required for notes.
- Trash names can't collide (timestamp plus a counter). `.trash` can't be reached through `/content` or the write API.
- `knownHost` and the CSRF guard cover the new routes because they mount under the same paths.

## Steps

Each phase ends green, committed, and with screenshots. The user can stop after any phase.

1. **Config model.**
   - Tri-state flags, mode defaults, `--home`/`--index`/`--theme`, module `nullOr` options.
   - Specs: the default matrix (read-only versus edit), and read-only module script parity with `main`.
2. **Home/index routing.**
   - `listFolder`, `views/folder.ejs`, `/` resolution, folder URLs, empty-dir empty state, home hidden from the tree, title link.
   - Specs: every row of the `/` resolution matrix, the empty dir, folder pages.
3. **Write API additions.**
   - Move, dirs, trash-delete, preview.
   - Specs: positive and negative for each, lock ordering, `.trash` unreachable.
4. **Sidebar.**
   - "+ New" rows, inline create (note and folder), empty folders in edit mode, title filter. Remove the dialog and the floating icon.
   - E2E specs, desktop and mobile.
5. **Editor rebuild.**
   - Layout, title rename, autosave chain, conflict banner, helpers, formatting bar, preview, delete dialog, `e`/Esc.
   - Specs: double/coalesced saves, typing during a save, `pagehide` flush, conflict both ways, list continuation table, rename collision.
6. **Mobile top bar and visual system.**
   - Tokens, button unification, the top bar.
   - Re-run the mobile specs. Screenshot QA.
7. **Task lists** (render + toggle) and **folder actions** on index pages (rename, delete when empty).
8. **README** (option table, notes quick start, kaloriina-style security note), `nix fmt`, lint, full suite, screenshots in the PR.

## Test strategy

- Unit-level through the HTTP API (the `request` fixture, raw `http` where Host or headers matter). E2E through Playwright on the desktop and Pixel 5 projects.
- Autosave timing is tested with `page.clock`, not sleeps.
- The default matrix is generated from the option table, so docs and code can't drift.

## Risks & trade-offs

- **`/` without a home file shows the index instead of the first note.** This is a behaviour change for read-only sites that have no `index.md`/`README.md`/`Home.md`. **Accepted by the user (2026-11-09)**: one rule for both modes. The changelog must call it out.
- **Home hidden from the tree** (the title is the link). A visible change for blogs. Low risk, intended.
- **Mode-dependent defaults** add one rule to learn. They're documented in a single table and every one can be overridden.
- **Autosave writes partial work to synced dirs.** Accepted; this is how notes apps behave. Ctrl+S remains as a reassurance.
- **No editor library.** The helpers cover what notes need. Syntax highlighting in the editor is a follow-up if wanted.
- **Size.** This is the largest change so far. The phases are independently shippable.

## Rollout

Same branch (`feat/notes`), one commit series per phase. A minor version bump with a changelog that lists the new flags and the `/` change.
