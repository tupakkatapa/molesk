# Plan: opt-in edit mode (private markdown notes)

> Superseded by [2026-11-09-hardening-and-polish.md](2026-11-09-hardening-and-polish.md).

## Goal

Let a private molesk instance create, edit and delete markdown notes (including nested folders) from the browser, while the default read-only docs host stays byte-for-byte unchanged.

## Revision: no built-in login

Supersedes every `--password-file` / Basic-auth / `passwordFile` commitment below. Same model as kaloriina: edit mode is a local tool.

- `--edit` defaults `--address` to `127.0.0.1`; an explicit non-loopback address starts with a warning (CLI) and an eval warning (module, containers exempt).
- Remote access goes through an HTTPS proxy that does the login (`tailscale serve`, Caddy `basic_auth`).
- `--allowed-host` / `allowedHosts`: in edit mode every request whose `Host` is not loopback or allowed gets 421 (DNS-rebinding defence; a loopback server with no login is otherwise writable by any web page via rebinding).
- Module: `StateDirectory` for the default data dir instead of a tmpfiles `d` rule, which would re-own a user-supplied (e.g. Syncthing-shared) directory.

## Success criteria

- `molesk ./notes --edit` on loopback: create `a/b/Idea.md` from the UI, edit it, save, delete it. Folders appear/disappear in the sidebar without restart.
- Without `--edit`: no edit UI in the DOM, `PUT`/`DELETE /api/files/*` return 404, all existing tests pass unchanged.
- `--edit` bound to a non-loopback address without `--password-file` exits 1 with a clear message (fail closed).
- With `--password-file`: every route returns 401 without valid Basic auth credentials.
- Concurrent edits never silently lose data: a stale save returns 412 and the editor offers recovery.
- Writes can't escape `CONTENTS_DIR`: `..`, encoded traversal, symlinked parent dirs, hidden segments and non-markdown extensions are all rejected.
- A crash mid-write never leaves a truncated note (atomic temp file + rename).
- NixOS module: `edit.enable` + `passwordFile` work under the existing `ProtectSystem=strict` hardening.
- The editor works on a phone: no zoom on focus, Save is reachable while the keyboard is open.

## Non-goals

- Rename/move, image/asset upload, search, version history (put the data dir in git or Syncthing).
- Multiple users, roles, sessions, logout, OAuth. One shared password, or delegate auth to a reverse proxy.
- Public read with authenticated editing. The password protects the whole site; any other split belongs in a proxy.
- Rich or WYSIWYG editing, live preview pane. Saving and viewing the rendered page is the preview.
- Editing in single-file mode (`molesk file.md --edit` is rejected at startup).

## Approach

### Scope

- One flag (`--edit`), one secret (`--password-file`). No config struct.
- One write primitive: `PUT /api/files/<path>`. A nested path runs `mkdir -p` on its parents, so "create subdir" and "create note" are the same action. There is no separate mkdir endpoint: empty folders are already hidden from the tree (`isDirectoryValid`), so a standalone mkdir would make a folder that then vanishes.
- `DELETE /api/files/<path>` handles files only. Folders that become empty already drop out of the tree; we don't prune them.
- No GET API. The `/edit/<path>` page embeds the raw text and its ETag server-side.

### Architecture

- `lib/auth.js`: `basicAuth(passwordFile)` middleware. Reads the file once at startup, stores the `sha256(password)` digest, and compares digests with `crypto.timingSafeEqual`. It ignores the username and sends `WWW-Authenticate: Basic realm="molesk"`. It mounts before every route, static files included. Failed attempts feed a **global** limiter (not per-IP), which returns 429 after 10 failures per minute. Per-IP throttling doesn't work here: the existing limiter skips loopback, and behind a reverse proxy every request comes from loopback.
- `lib/edit.js`: exports `editRouter(config, onChange)` (an `express.Router`):
  - `GET /edit/:path(*)` renders `index` with an `editor` local (raw text, ETag, relative path, `isNew`). The path goes through `resolveWritable` too, so a read through a symlinked dir can't escape the root.
  - `PUT /api/files/:path(*)` uses `express.text({ type: "text/markdown", limit: "1mb" })`.
  - `DELETE /api/files/:path(*)`.
  - `resolveWritable(root, rel)`: shared path validation (see Security).
  - `writeAtomic(file, data)`: write `.<name>.<random>.tmp` in the same dir with the existing file's mode (new files get the default), `fsync`, `rename`, then `fsync` the directory.
  - `withLock(file, fn)`: per-path promise chain, which makes the ETag check and the write atomic within the process. `ponytail:` single-process lock; it doesn't cover multiple molesk processes sharing a dir. The ETag still catches external writers.
- `app.js`: mounts the router only when `config.EDIT`. It also exposes `invalidateAll()` (folder cache + `rssFeedCache`) and passes it as `onChange`, so a redirect after save never shows a stale sidebar. `fs.watch` debounce is not a reliable signal for this.
- Content actions dedupe: move the download button, and the new edit button, into one helper `contentActions(relPath, config)` in `lib/helpers.js`. Both the AJAX branch in `app.js` and `index.ejs` use it, which removes the existing duplicated download markup. URL-encode each segment of the href. This also fixes the current unencoded `/download/<path with spaces>`.
- `views/editor.ejs` partial is included by `index.ejs` in place of `initialContent` when `editor` is set. `public/editor.js` and `public/editor.css` are linked only when `config.EDIT`. The read-only HTML stays identical apart from the deduped actions.
- Sidebar: one "New note" button (pencil-plus icon) in `.sidebar-header`, rendered only in edit mode. It opens a native `<dialog>` with one path input, prefilled with the current note's folder (`posts/`). Submitting navigates to `/edit/<path>` (`.md` appended if missing). The client rejects an empty last segment such as `posts/`. Saving a new note uses `If-None-Match: *`.

### HTTP semantics (concurrency and CSRF)

- ETag = `"sha256-<hex>"` of the file bytes, computed on read and on write.
- `PUT` with `If-Match: <etag>` updates the file and returns 412 if the file changed or was deleted.
- `PUT` with `If-None-Match: *` creates the file and returns 412 if it already exists.
- `PUT` without either header returns 428. The editor's explicit "Overwrite" sends `If-Match: *`.
- `DELETE` requires `If-Match: <etag>` and returns 412 or 428 the same way.
- Responses: `200` on update and `201` on create, both with an `ETag` header. The editor switches a new note to update mode using that ETag. Delete returns `204`. Errors use `{error}` JSON.
- CSRF: `Content-Type: text/markdown` and the `DELETE` method are both non-simple, so a cross-origin request must pass a CORS preflight. We never answer preflights. Defence in depth: reject mutating requests whose `Sec-Fetch-Site` is present and not `same-origin` (403).

### Security

- Fail closed at startup in `lib/cli.js` validation:
  - `--edit` + `SINGLE_FILE` → exit 1.
  - `--edit` + non-loopback `HOST` (not `127.0.0.1`, `::1` or `localhost`) + no `--password-file` → exit 1. The message points to `--password-file` or a loopback bind behind a proxy.
  - An unreadable or empty password file → exit 1.
- `resolveWritable`:
  - Decode the path, split it on `/`, and reject segments that are empty, `.`, `..`, start with `.`, or contain NUL or control characters. Each segment is at most 255 bytes.
  - The extension must be in `MD_EXTENSIONS`.
  - `realpath` the nearest existing ancestor and require it under `realpath(CONTENTS_DIR)`. This blocks symlinked dirs. `rename` replaces a symlink leaf instead of following it.
  - Reuse `isPathSafe` as the first gate.
- With `--password-file`, every response gets `Cache-Control: private`. Edit pages and the API get `no-store`. Shared caches must never hold private notes.
- The README recommends a high-entropy password (`openssl rand -base64 24`). Together with the global failure throttle, this makes online guessing infeasible.
- The Basic password travels in clear over HTTP. The README states that TLS (a reverse proxy) is required for non-loopback use.
- CSP is unchanged: no inline script, and editor assets are same-origin.

### Reliability

- Atomic write via temp file + `fsync` + `rename`, in the same directory so the rename is atomic on the same filesystem. Unlink the temp file on failure.
- The per-path lock serialises check-then-write. The ETag protects against other writers (vim, Syncthing, a second tab or device).
- Map errors explicitly: `ENOENT`→404/412, `EEXIST`→412, `EACCES`/`EROFS`→500 with a log line. Never expose fs paths in responses.
- The client sets a `beforeunload` guard while there are unsaved changes and clears it after a successful save.
- On 412 the editor keeps the user's text and shows "Changed elsewhere", with Reload (discard) and Overwrite actions.

### UX (desktop and mobile)

- Edit button (pencil): placed next to the download icon in the content actions, 44px on coarse pointers.
- Editor page:
  - Sticky toolbar: path, Save, View, Delete. It stays visible above the on-screen keyboard (`position: sticky; top: 0`).
  - Full-width `<textarea>` with `font-size: 16px` (no iOS focus zoom), monospace, `spellcheck`, `autocapitalize="sentences"`, `enterkeyhint="enter"`.
- `Ctrl/Cmd+S` saves. The existing `t` shortcut is already suppressed inside a TEXTAREA.
- Delete uses native `confirm()`, then navigates to `/`.
- Status line (`aria-live="polite"`): "Saved" or the error text.

### NixOS module

- New options:
  - `edit.enable` (bool, default false).
  - `passwordFile` (`types.nullOr types.str`, default null; a runtime path, never copied to the store).
- When `edit.enable`:
  - `ReadWritePaths = [ cfg.data ]`.
  - `systemd.tmpfiles.rules = [ "d ${cfg.data} 0750 ${cfg.user} ${cfg.group} -" ]`.
- `passwordFile` is set: `LoadCredential = "password:${cfg.passwordFile}"` and the flag `--password-file "$CREDENTIALS_DIRECTORY/password"`.
- Assertion: `edit.enable && passwordFile == null` requires a loopback `address`. This mirrors the runtime check, so a misconfiguration fails at eval time.

### Docs

- README:
  - "Edit mode" section: what it does, flags, module example, auth and TLS warning, concurrency behaviour, non-goals.
  - Add the new options to the Options list and the CLI help block.
- `displayHelp()` gains `--edit` and `--password-file`.

## Test strategy

- Positive: create, nested create, update, delete, auth success, sidebar refresh after write, mobile editor ergonomics.
- Negative: every `resolveWritable` rejection class, 401/403/412/413/428, startup refusal matrix, read-only mode exposing no write surface.
- Characterisation: the existing suite runs unchanged against the read-only server and is the regression proof.

## Risks & trade-offs

- **Pre-existing issue, out of scope.** The read route `/content/*` follows symlinks out of `CONTENTS_DIR`, because `isPathSafe` checks the path text only. File a follow-up issue. Edit mode's own paths are realpath-checked.
- **Whole-site password, not split read/write.** Simplest correct model for "private instance". A public blog with web editing should use proxy auth instead. Revisit if asked.
- **Basic auth.** Native in every browser and on mobile, zero dependencies, no session state. Costs: no logout, and it needs TLS. Accepted.
- **No rename.** Users can delete and re-create. Rename is the most likely follow-up (`POST /api/move` with the same validation).
- **The in-process lock doesn't span processes.** The ETag still prevents silent overwrite. Documented via a `ponytail:` comment.
- **Merge order with the mobile plan.** Both touch `index.ejs`, `app.js` (AJAX actions) and possibly `sidebar.css`. Merge the mobile branch first, then rebase this branch. Editor styles live in `editor.css` to keep overlap small.

## Rollout

- Opt-in flag, default off. No migration. Existing deployments are unaffected.
- Minor version bump plus a changelog entry via `/tt:act:bump` after merge.
